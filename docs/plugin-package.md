# Knowledge Work SDLC plugin package

This generated package supplies a file-native professional-work method to
Codex, Claude Code, and Claude Cowork. It contains skills, bounded specialist
definitions, readable recipes, durable artefact templates, documentation, and
four optional buy-side company-model skills with shared references. It contains no Python runtime, lifecycle
hooks, credentials, connectors, or model router.

## Install

- **Claude Cowork:** open **Cowork → Customize → Plugins**, add a custom plugin,
  select the ZIP, and attach the client workspace.
- **Claude Code:** extract the ZIP and start a new process with
  `claude --plugin-dir /absolute/path/to/extracted-package`.
- **Codex:** add the package through a local or managed plugin marketplace. For
  work in a local Git repository, the source repository's `install.sh` route is
  simpler and also installs the standing `AGENTS.md` contract.

Start a new task or conversation after installation. State the commission
normally; explicit invocation of `knowledge-work` is available for diagnosis
but is not the intended everyday entry.

```text
Review the supplied evidence, distinguish what it states from what you infer,
and produce a decision brief that makes the unresolved question explicit.
```

## Workspace and resources

The active client workspace owns `ai_docs/` initiative state and professional
outputs. The package's generated skills and agents resolve their shared method
resources under `resources/.knowledge-sdlc/` relative to the package root.
Those bundled recipes and templates are method inputs, never project facts.
Optional buy-side references follow the same resource binding; logical
`.knowledge-sdlc/...` cues refer to that managed root. Availability does not
select the helpers for every run or approve the client's financial method.
On a fresh attached workspace, the entry skill creates only the neutral
initiative index before creating the files earned by the first commission.

A plugin does not supply the external capability named by a commission. Excel,
connectors, MCP servers, CLIs, credentials, and protected client files remain
host- or workspace-owned. The orchestrator binds only a facility it can observe
and prove for the exact actor and operation; otherwise it narrows or stops the
work visibly.
