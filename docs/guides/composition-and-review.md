# Composition and review

## From commission to execution plan

The orchestrator begins with the nearest human-readable recipe, then adapts it
to the actual commission. A recipe is a tested route through methods, not an
intent classifier or executable workflow.

The library supplies six starting points: professional research, source
interpretation, independent challenge, protected-artifact update, correction,
and domain-method adaptation. These are route families rather than a closed
intent vocabulary. A commission may combine them, and a genuinely different
commission may be decomposed directly while preserving the same authority and
artefact rules.

For each possible method, the run record states:

- the uncertainty, consequence, authority, or continuity need it serves;
- its exact durable inputs and expected output;
- why it is included, excluded, reused, or degraded;
- whether fresh context or independence is required; and
- the first legal action and stop condition.

Python checks that recipe names resolve to real method declarations and that
their mechanical I/O relations are coherent. It never selects the recipe or
decides whether a semantic trigger is true.

## Skill or specialist

A skill is performed by the main agent when the work needs the commissioner's
interaction or must remain in the main context. A specialist is used when
freshness, independent challenge, context isolation, or a bounded tool grant
materially improves the outcome.

The main agent is the only caller. A specialist receives a packet of durable
paths, authority, exclusions, tools, output, and stop condition. It cannot spawn
another worker or route the run.

## When review is earned

Review is required when an inference or source treatment could materially
change a consequential decision or protected action. Low-consequence work may
prune review, but a plan which requires review cannot pass with a decorative
placeholder.

```text
review required + reviewer available
→ fresh challenge artefact before disposition

review required + reviewer unavailable
→ explicit degraded or blocked gate

consequential promotion
→ exact human disposition after challenge
```

The reviewer receives the candidate, settled meaning, evidence, and a sealed
purpose-specific packet, not the producer transcript. Findings cite exact
evidence and are ranked by consequence. The reviewer does not promote or repair
the candidate it is reviewing.

## Failure and retry

A failed method remains a stage outcome even if fallback succeeds. A correction
changes every recorded dependant and preserves old revisions. The invalidation
map names each stale object's owning producer; orchestration re-enters that
producer to create one typed successor before any newly earned challenge or
disposition. Reconciliation and re-derivation diagnose consequences but do not
stand in for corrected production. Retrying does not create a parallel run
unless the prior run is closed or the user commissions a new attempt.
