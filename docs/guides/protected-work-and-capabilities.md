# Protected work and runtime capabilities

## A template is an input contract

A **client template** is a workbook, document, slide deck, or other native
object supplied for one initiative or project. It is different from the
Markdown artefact templates bundled with the harness: bundled templates shape
the harness's own records; a client template shapes or constrains the
professional deliverable.

A user-owned template may be:

- **shape-bearing:** layout, sheets, tables, styles, charts;
- **method-bearing:** formulas, valuation conventions, scenario mechanics;
- **policy-bearing:** locked regions, disclaimers, approvals; or
- a combination.

The run binds its exact path or provider reference, content hash, owner,
revision, role, precedence, editable/protected objects, native features,
candidate location, and structural, formula, computational, visual,
professional, and provenance checks.

The original is never an experimental workspace. Production targets a
candidate copy. A successful open or save is not fidelity proof.

Supply it in the commission by naming the exact file or provider object and the
intended use:

```text
Use models/House Model.xlsx as the protected template. Update Q2 actuals in a
candidate copy, preserve all forecast cells and named ranges, recalculate and
render the summary sheets, and do not replace the original without my explicit
decision.
```

## Capability preflight

The orchestrator owns two depths after the commission is concrete.

**Reconnaissance** asks whether a plausible facility is visible, reachable,
authenticated, apparently authorised, and able to reach the asset.

**Operation proof** checks that the eventual producer can perform the exact
read, inspect, candidate write, recalculate, render, query, export, or validate
operation. The probe and production actor must have the same facility and
authority.

The binding records semantic capability, actual facility, actor, observed
version, auth/scope, probe/result, permitted operation, fallback, and claim
limit. Tool metadata is a hint. There is no connector registry or preflight
sub-orchestrator.

The harness does not install Excel, log into a data vendor, or provision an MCP
server. The user or organisation exposes whatever facilities are available in
the host. Once the concrete plan says what must be done, the orchestrator maps
the need to those visible facilities and proves only the exact operation the
producer will use. If no suitable facility exists, it returns a research note,
change specification, or other honest degraded output only when that object is
still useful; it never counterfeits a native workbook.

## Protected promotion

Promotion requires an exact candidate identity, current protected identity,
successful relevant checks, recoverable replacement route, and explicit human
Use authority for that target and scope. A mismatch leaves the original
unchanged. Promotion produces a durable record and rollback handle; it does not
convert the candidate's professional claims into truth.
