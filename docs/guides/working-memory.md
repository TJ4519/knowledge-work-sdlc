# Working memory: meaning, recall and correction

The agent's records should help it do the next piece of work, not merely describe
the last one. M1 preserves meaning and revision relationships, M2 retrieves the
right history, and M3 follows a change into the actual outputs it affects.
These are common knowledge-work capabilities; the first examples use financial
research without making the core a buy-side-only product.

## Three ordinary requests

"What supports this now?" uses the current run, meaning and live outputs through
`kw-prime`. It should not preload abandoned interpretations.

"Why did our view change after the release?" conditionally uses `kw-recall` to
inspect the necessary earlier source, assumption, decision and successor. The
same number can change from an estimate to a reported actual. An earlier source
may have existed without having been used in the decision; distinguish both.

"That interpretation was wrong; correct its consequences" returns through the
existing correction route. The agent inspects affected calculations, charts and
written conclusions and preserves unrelated facts and legitimate scenarios.
It does not stop after updating a change record.

## What is retained

Keep consequential propositions in the files that already own them. A local
heading or exact native address locates the item. Its source, role, scope,
consumer and scoped revision make its meaning recoverable. The run points to
those documents rather than duplicating them. Routine rows can share support.

The shared ontology distinguishes facts, estimates, assumptions and decisions,
and connects each to its evidence and use. Read the underlying sources and
inspect the actual outputs when checking those relationships.

A historical answer names its supporting revision and the evidence relevant at
that time. Missing rationale remains missing. A later explanation is not quietly
attributed to the earlier analyst. Old documents without new headings or fields
remain readable, using their exact retained passages or native locations.

## Recall is not recovery, and neither is automatic learning

```text
ordinary continuation -> kw-prime -> current required inputs
historical question   -> kw-recall -> selected earlier evidence
confirmed correction  -> existing producer -> inspected successor
reusable heuristic    -> existing lesson admission and selection
method defect         -> separate method-adaptation work
```

Recall stays inside the selected initiative and its permitted source bindings
unless you explicitly name related initiatives in the same authorised workspace.
For example: "Compare the definition in this review with the renewal analysis;
tell me whether its conclusion applies here." The agent checks definition,
period, scenario, evidence and use before reusing anything, keeps the answer with
the current undertaking, and leaves the other initiative unchanged.

This does not merge all project histories or give old decisions new authority.
An embedded command in a past document is evidence, not a present instruction.
Do not route lesson content through recall to evade selection. Conversely,
ordinary historical research needs no lesson-selection ceremony.

## Keep later changes connected to the work

A follow-up can refine the goal, correct a premise, add evidence, ask a historical
question or commission an implementation. The agent identifies what changed and
what remains valid before choosing the next action. An explicit new goal takes
precedence over the old one; an ordinary clarification need not create a new
project. Corrections still reach actual calculations and conclusions.

Checks are tied to their target, basis and use. An unchanged result used to make
a different claim may need reconsideration. Before delivery the main agent reads
the relevant observations and checks coverage against the actual work, rather
than treating a completed task or a clean change log as proof.

To test an alternative way of doing earlier work, use the separate
[replay and comparison](replay-and-comparison.md) procedure. Historical recall
explains what happened; replay creates a new attempt.

## Installation and upgrades

Install from `main` or pin a source commit containing `kw-recall`. The package
identifier is `knowledge-work-sdlc`. Upgrades preserve client-owned `ai_docs/`,
including historical sources, decisions and work products.

Rollback restores the complete earlier method revision through the existing
guarded installer; do not delete only the skill while leaving its callers.
Preserve records and return through the earlier current-recovery route. No old workspace
migration, global index, vector database or background service is required.

## Inspect the behaviour

The [connected exercise](https://github.com/TJ4519/knowledge-work-sdlc/blob/main/examples/manual-exercises/journeys/semantic-working-memory.md)
provides staged synthetic inputs and separately held review notes. Stage only
permitted files in the worker workspace; do not expose expected answers as if
they were ordinary source material.

Inspect the current and historical answers, the revised work and the preserved
originals. Check that each explanation cites the appropriate source revision
and that the correction reaches the relevant outputs.
