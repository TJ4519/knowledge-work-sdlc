# Knowledge Work SDLC documentation

The shortest path is to run one commission, then read the mechanism that
explains what you observed.

## Use it

- [Getting started](getting-started.md) installs the harness and walks through a
  commission, correction, and fresh-task continuation.
- [Installation and provider boundaries](guides/installation-and-providers.md)
  gives repository, upgrade, Codex, Claude Code, and Cowork routes.

## Understand it

- [Methodology](methodology.md) explains the governing problem, invariants,
  artefact bus, composition primitives, and converge-diverge-converge shape.
- [Design](../DESIGN.md) maps that method to exact files, runtime authority,
  source/workspace/plugin shapes, and deliberate absences.
- [Composition and review](guides/composition-and-review.md) explains how a
  recipe becomes a run-specific plan and when fresh challenge is earned.
- [Continuity and recovery](guides/continuity-and-recovery.md) explains how a
  new agent resumes without a transcript recap.

## Tailor it

- [Expert-owned method extensions](guides/expert-extensions.md) covers import,
  curation, binding, update, retirement, and removal.
- [Protected work and runtime capabilities](guides/protected-work-and-capabilities.md)
  covers client templates, candidate copies, connectors, MCPs, and tool probes.
- [Governed personalisation](guides/personalisation.md) separates present-run
  correction, project knowledge, recurring failure, method change, and a
  reusable personal lesson.

## Maintain and test it

- [Maintaining the harness](guides/maintaining-the-harness.md) explains the
  canonical source, generated projections, validation, packaging, and release
  boundary.
- [Plugin package guide](plugin-package.md) is the self-contained README placed
  in generated Codex/Claude packages.

The conceptual reading order is methodology → design → mechanism guides →
`AGENTS.md` → individual skills. The practical reading order is getting started
first, then only the mechanism needed for the work at hand.
