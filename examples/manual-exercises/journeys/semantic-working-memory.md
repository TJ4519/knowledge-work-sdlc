# Semantic working memory: connected exercise

Use the fictional Northstar materials to exercise meaning, historical inquiry
and scoped correction in documents.

## Operator preparation

Use a disposable client repository with the harness installed. Keep this
journey and the review notes outside the producer's readable workspace. Copy
only each stage's files when that stage is reached; do not mount the entire
source repository or later stages. The installed method may be available, but
not the expected-answer material. If isolation is not available, label the
exposure in the exercise record.

The inputs are under `../fixtures/semantic-working-memory/` relative to this
journey: stage-1, stage-2, stage-3 and stage-4. Use the exact ordinary requests,
not a paraphrase containing expected answers. Keep a starting snapshot and
freeze each delivery before the next stage. Preserve failed activation, missing
capabilities and unexpected user interruptions rather than silently restarting.

## Run sequence

Stage 1 produces useful analysis and its own working records from the initial
source and request. Do not supply a completed memory or expected mapping.
Stage 2 supplies the subsequent release and update request. Stage 3 supplies
the correction; an already-correct treatment may be inspected and retained.
Stage 4 uses a genuinely fresh session if available and asks the current and
historical questions. Retain the actual outputs and read/operation evidence.

A source-aware reviewer may inspect final outputs and the review notes only
after delivery is frozen. The reviewer must not repair its reviewed object.
One person role-playing both actors is not an independent review. Do not turn
this exercise into a new benchmark campaign or add required model contexts
without the operator's actual resource authority.

## Review notes: operator only

Q2 100 was initially an internal forecast and later became a reported actual.
No reason for choosing the initial forecast is supplied; an invented rationale
is a failure. Q1 remains 80. Q3 internal deliveries remain 110, but recognised
revenue under the correction is 90 (110 minus 20); the 20 is timing into Q4,
not a forecast of total Q4 revenue. Management guidance remains the separate 118.
The internal recognised-revenue change from Q2 is -10%, not +10%; any affected
outlook must use the corrected interpretation or explicitly avoid that claim.

Inspect whether the producer actually wrote useful analysis and updated both
requested outputs. A clean evidence map does not compensate for a stale outlook.
Check preservation of earlier delivered files, current pointers and applicable
source support. A correct explanation without a changed output does not prove
repair. A legitimate difference from management is not an inconsistency to erase.

Challenge the rubric itself: could these visible examples be hard-coded while
ordinary work remains wrong? Before an additional authorised probe, freeze a
variation and its expected consequence. Useful variations change the numbers,
remove the rationale, introduce a parallel scenario, or omit a recorded consumer
while leaving the dependency visible in the actual output. Include an ordinary
successful task that requires no historical reading. Do not penalise a valid
alternative representation merely because it differs from a preferred layout.

Record source inspection, actual method activation, observed answers, correction
coverage, preserved work and any unresolved findings.
